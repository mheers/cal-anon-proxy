<objective>
Fix two bugs in reader.go: the unchecked calendars[0] slice access that panics on empty upstream responses, and the missing HTTP client timeout that allows the sync goroutine to hang indefinitely on a slow/unresponsive upstream.

Purpose: A proxy that hangs or crashes on upstream failures is worse than one that degrades gracefully. These are pure reader.go changes with no dependency on Plan 01.

Output: reader.go with a guarded calendars slice access and a fully configured http.Client with client + transport level timeouts.
</objective>

HTTP timeout pattern to apply (from GO_CONCURRENCY research):
```go
import "net"

httpClient := &http.Client{
    Timeout: 30 * time.Second,
    Transport: &http.Transport{
        DialContext:         (&net.Dialer{Timeout: 5 * time.Second}).DialContext,
        TLSHandshakeTimeout: 5 * time.Second,
    },
}
```

```go

    return nil, fmt.Errorf("no calendars found for source %s", src.URL)
}
calendar := calendars[0]
```
