## Directory Purposes

**Root (`.`):**
- All application Go files are in `package main`
- Business logic (proxy fetch, sanitization, CalDAV serving) coexists with wiring in a flat package
- Key files: `main.go`, `config.go`, `proxy.go`, `reader.go`, `calendar.go`, `middleware.go`

**`pages/`:**
- htmgo SSR page functions; each file returns `*h.Page`
- `root.go` is excluded from automatic route registration (via `htmgo.yml`: `automatic_page_routing_ignore: ["root.go"]`)
- `index.go` defines the sole real page (`IndexPage` → routed to `/`)

**`partials/`:**
- htmgo HTMX partial functions; each returns `*h.Partial`
- `CounterPartial` in `index.go` is a framework scaffold demo; not used by the calendar UI

**`__htmgo/`:**
- Fully generated by the `htmgo` CLI tool — regenerated on `htmgo run/build`
- `assets/assets-generated.go` provides typed Go constants for all public asset URLs
- Never edit manually; changes will be overwritten

**`assets/`:**
- `css/input.css` — Tailwind source; compiled by htmgo build pipeline
- `dist/` — build output; served as static files at `/public/*` in dev and embedded at prod build time
- `public/` — original icon sources

**`internal/embedded/`:**
- `OsFs` is a trivial `fs.FS` wrapper over the OS filesystem, used in dev mode so assets are served directly from disk without embedding

**`ci/dagger/`:**
- Dagger CI pipeline in TypeScript with vendored Dagger SDK
- Used for container build and push; invoked by GitHub Actions

## Key File Locations

**Entry Points:**
- `main.go`: Application start — config, proxy, CalDAV handler, auth, sync goroutine, HTTP server

**Configuration:**
- `config.go`: `Config` struct with all env vars; `ReadConfig()` entry
- `.env.example`: Canonical list of required environment variables
- `htmgo.yml`: htmgo framework settings (Tailwind, file watching, routing)
- `tailwind.config.js`: Tailwind CSS config

**Core Business Logic:**
- `reader.go`: All upstream CalDAV fetching and event anonymization/normalization
- `calendar.go`: In-memory CalDAV backend implementation and `SetEvents()` update logic
- `middleware.go`: HTTP Basic Auth enforcement

**Web UI:**
- `pages/index.go`: Calendar viewer page with FullCalendar.js integration
- `pages/root.go`: Shared HTML shell layout

**Infrastructure / Generated:**
- `__htmgo/setup-generated.go`: Route wiring entry point
- `__htmgo/assets/assets-generated.go`: Asset path constants

**Testing:**
- `reader_test.go`: Integration test against a live CalDAV source

## Naming Conventions

**Files:**
- Snake-case for multi-word Go files: `reader_test.go`, `assets_prod.go`
- Generated files suffixed with `-generated`: `pages-generated.go`, `assets-generated.go`
- Build-tag variants use suffix: `assets.go` (dev) / `assets_prod.go` (prod)

**Packages:**
- Root files: `package main`
- `pages/`: `package pages`
- `partials/`: `package partials`
- `__htmgo/`: `package __htmgo`
- `internal/embedded/`: `package embedded`

## Where to Add New Code

**New upstream calendar source:**
- Add `Src5*` fields to `Config` in `config.go`
- Add corresponding branch in `Config.Srcs()` in `config.go`
- No changes needed to `reader.go` — it iterates `Srcs()` generically

**New event transformation/sanitization logic:**
- Add helper functions to `reader.go`; call from `download()` in the per-VEVENT loop

**New CalDAV backend behavior:**
- Modify `calendarBackend` methods in `calendar.go`

**New web page:**
- Create `pages/<name>.go` with a function returning `*h.Page`
- Run `htmgo run` or `htmgo build` to regenerate `__htmgo/pages-generated.go`

**New HTMX partial:**
- Create function in `partials/index.go` (or new file) returning `*h.Partial`
- Regenerate via htmgo CLI

**New middleware:**
- Add to `middleware.go`; wire in `main.go`

**New utility shared across files:**
- Add to root `package main` — all root `.go` files are in the same package

## Special Directories

**`__htmgo/`:**
- Purpose: Code-generated route and asset registration
- Generated: Yes — by `htmgo run`/`htmgo build`
- Committed: Yes (checked in)

**`assets/dist/`:**
- Purpose: Compiled CSS and copied static files
- Generated: Yes — by htmgo/Tailwind build
- Committed: Yes (required for prod embed)

**`ci/dagger/sdk/`:**
- Purpose: Vendored Dagger TypeScript SDK
- Generated: Yes — managed by Dagger
- Committed: Yes
